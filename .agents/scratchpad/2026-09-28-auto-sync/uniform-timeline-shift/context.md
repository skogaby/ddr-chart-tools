## Functional requirements (from task)

1. **FR1.** `src/job/sync_offset.rs`: `shift_timeline(song, tempo_pairs,
   delta_ms) -> Result<(), JobError>`.
   - Uniform shift of every `tempo_pairs[i].1` and of
     `song.audio_sync_offset_seconds` by δ/1000 s.
   - δ = 0 is a no-op.
   - Checked arithmetic. On overflow return
     `JobError::SyncShiftOverflow { delta_ms }` with no mutation.
2. **FR2.** Delete `apply_sync_offset` (`src/job/mod.rs`).
3. **FR3.** Apply the bias on all four paths at the R10 bias position:
   - `sm5_to_ddr` and `legacy_to_ddr`: on the final pairs from
     `synthesize_events`, and on the song;
   - `ddr_to_sm5`: on the song, with empty pairs;
   - `legacy_to_sm5`: on the song and the raw pairs.
4. **FR4.** Docs:
   - `Job::sync_offset_ms` doc comment;
   - `--sync-offset-ms` help text;
   - `product.md` rule 10 and the *Sync offset* glossary entry;
   - README *Sync Offset* section, with the +53 ms figure flagged as under
     re-validation.

## Acceptance criteria (task AC1–AC8)

1. Legacy → DDR: every anchor shifts by N; ticks and consecutive
   differences are unchanged.
2. Single-BPM regression: the final pair moves by N.
3. SM5 → DDR honors the bias.
4. SSC outputs: `#OFFSET` is N/1000 lower, `#BPMS` and `#STOPS` are
   unchanged. New behavior for `DDR → SM5`; unchanged for
   `DDR_LEGACY → SM5`.
5. No bias gives output identical to before.
6. Overflow returns an error with no mutation.
7. `apply_sync_offset` is gone and the docs are updated.
8. `fmt`, `clippy` and `test` gates pass.

## Interpretation and assumptions (auto mode)

- **A1.** Path-level tests exercise the real direction functions through
  `run_one` with tiny synthetic inputs in a temp dir (1 s of silence),
  rather than refactoring the paths into pure functions.
  - This tests the actual wiring.
  - The task permits building values directly, but going through files is
    more faithful and needs no refactor.
- **A2.** AC5 ("identical to before") is verified two ways:
  - a unit test that δ = 0 is a no-op;
  - a one-off manual comparison of outputs from a binary built at `HEAD`
    before the change against the new binary, with no bias, on the same
    synthetic inputs, recorded in `progress.md`.

  AC4's "unchanged for `DDR_LEGACY → SM5`" is checked the same way, with a
  nonzero bias.
- **A3.** The legacy → DDR bias is now applied after `synthesize_events`
  (the design's order).
  - The pre-change order was: shift the first pair, then extrapolate.
  - The trailing extrapolated pair is now computed from unshifted slopes and
    then shifted uniformly. That is equivalent to shifting everything first.
- **A4.** On `DDR_LEGACY → DDR` with an XWB passthrough, the bias touches
  only the SSQ, as today.
- **A5.** Negative δ is allowed. The CLI already accepts hyphen values.

## Non-functional

- **No partial mutation on overflow.** Compute all new values first, then
  write.
- **Overflow is practically unreachable** (anchors are far below 2³¹ ms);
  the error exists for correctness.
