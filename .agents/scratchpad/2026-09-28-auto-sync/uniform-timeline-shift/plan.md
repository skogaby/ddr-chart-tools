## Test scenarios

### Unit tests: `src/job/sync_offset.rs`

1. **`shifts_every_pair_and_preserves_slopes_and_stops`**
   - Input pairs: `[(0, 20), (4096, 2020), (8192, 4020), (8192, 4520),
     (16384, 8520)]` (four beats per 2000 ms, then a 500 ms stop, then a
     segment). δ = +53. Model offset starts at 20/1000.
   - Expected pairs: `[(0, 73), (4096, 2073), (8192, 4073), (8192, 4573),
     (16384, 8573)]`, i.e. every tick unchanged and every consecutive
     difference unchanged. Offset becomes 73/1000.
2. **`single_bpm_song_moves_its_final_pair`** (regression, AC2)
   - `[(0, 0), (118784, 58000)]`, δ = 53 → `[(0, 53), (118784, 58053)]`.
3. **`negative_shift_moves_everything_earlier`**
   - δ = −30 on the scenario 1 input: every value decreases by 30 and the
     offset becomes −10/1000.
4. **`zero_shift_is_a_no_op`**
   - δ = 0: pairs and offset are bit-identical.
5. **`empty_pair_list_shifts_only_the_model_offset`**
   - δ = 7 with `&mut []`: offset +7/1000.
6. **`overflow_is_reported_without_mutation`**
   - Positive: pairs `[(0, 0), (4096, i32::MAX - 5)]`, δ = 10 →
     `Err(JobError::SyncShiftOverflow { delta_ms: 10 })`; pairs and offset
     unchanged.
   - Negative: `[(0, i32::MIN + 3)]`, δ = −10 → the same error.

All six fail to compile or fail against the absent implementation.

### Path tests: `src/job/mod.rs` test module, through `run_one`

A helper writes synthetic inputs to a `tempfile::tempdir()`:

- a two-segment song (160 BPM from beat 0, 120 BPM from beat 16), with one
  chart and taps up to beat 40, plus a 0.5 s stop at beat 24;
- 1 s of 44.1 kHz stereo silence;
- a chart encoded as SSC (for SM5 inputs) or SSQ (for DDR / DDR_LEGACY
  inputs, via `ssq::writer::write` with synthesized pairs and events);
- audio encoded as OGG (SM5) or XWB + XSB via `write_ddr_audio` (DDR /
  DDR_LEGACY).

Each test runs the job with `sync_offset_ms = 0` and with `sync_offset_ms =
N`, re-parses both outputs, and compares:

7. **`sm5_to_ddr_applies_bias_to_every_anchor`** (AC3)
   - The two outputs' `raw_tempo_pairs` have identical ticks.
   - Every `tempo_data` differs by exactly N = 25.
8. **`legacy_to_ddr_applies_bias_to_every_anchor`** (AC1)
   - Same as scenario 7, with N = 53, on a `DDR_LEGACY` input.
   - Also asserts the final pair moved, the regression through the real path.
9. **`ddr_to_sm5_applies_bias_to_offset`** (AC4)
   - The re-parsed SSC `audio_sync_offset_seconds` differs by exactly
     N/1000, with N = 25.
   - `tempo_segments` and `stops` are equal.
10. **`legacy_to_sm5_applies_bias_to_offset`** (AC4)
    - Same assertions as scenario 9, on a `DDR_LEGACY` input.

Scenarios 7 and 9 fail today, because the bias is ignored on those paths.
Scenario 8 fails today, because only the first pair moves. Scenario 10
passes today and is a regression guard that must keep passing.

## Implementation approach

1. **New file.** `src/job/sync_offset.rs` with a `//!` header.
   `shift_timeline` computes all new `tempo_data` values with
   `i32::checked_add` into a temporary `Vec`, and the new offset with
   `Rational::new(delta, 1000)` then `add`. Only after everything succeeds
   does it write the values back.
2. **Error variant.** `JobError::SyncShiftOverflow { delta_ms: i32 }`: "shifting
   the chart by {delta_ms} ms overflows its timing".
3. **Wire the paths** in `src/job/mod.rs`:
   - **`sm5_to_ddr`:** `let (events, mut tempo_pairs) = synthesize_events(..)`,
     then `sync_offset::shift_timeline(&mut song, &mut tempo_pairs,
     job.sync_offset_ms)?`, then write.
   - **`legacy_to_ddr`:** remove the `apply_sync_offset` call. After
     `synthesize_events`, shift `result.song` and the final pairs.
   - **`ddr_to_sm5`:** after audio assignment, `shift_timeline(&mut
     result.song, &mut [], job.sync_offset_ms)?`.
   - **`legacy_to_sm5`:** replace the call with `shift_timeline(&mut
     result.song, &mut result.raw_tempo_pairs, ..)?`, keeping its position
     after `modernize`.

     Ordering relative to `.sif` metadata and audio decode doesn't matter,
     but the bias must stay at the end per R10. Move it to just before
     writing, for consistency with the other paths.
   - Delete `apply_sync_offset`.
4. **Docs:** help text, `Job` doc comment, `product.md`, README.

## Reasoning and risks

- **Path tests go through `run_one`,** so they test the actual wiring and
  the real writers and parsers, with no mocks. The inputs are tiny (1 s of
  audio), so they stay fast even in debug builds.
- **The OGG encoder** (`vorbis_rs`) on 1 s of silence is fast. The ADPCM
  encoder likewise.
- **SSC re-parse precision:** `#OFFSET` is written with 6 decimals, so
  N/1000 compares exactly as a `Rational` after re-parse.
- **Risk:** synthesized SSQ inputs for the legacy paths need `tps == 1000`.
  Modernize is then a no-op rescale; `tds_shift` zeroes `tempo_data[0]`.
  The input song's offset is 0 to keep expectations simple.
