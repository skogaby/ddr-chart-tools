# Calibration Corpus: Stock DDR World + Community Offsets

Answers Q1. Feeds D7 (target offset), D8 (confidence thresholds), and the
estimator accuracy check.

## Sources

- **Stock songs** — a live DDR World install, referenced through the
  `$DDR_WORLD_INSTALL` environment variable:
  - charts: `$DDR_WORLD_INSTALL/data/mdb_apx/ssq/<code>.ssq` (1,605 files; 46
    are split charts named `<code>_<n>.ssq`, e.g. `acef_1.ssq`, and are
    excluded from calibration)
  - audio: `$DDR_WORLD_INSTALL/data/sound/win/dance/<code>.xwb` + `.xsb`
    (1,559 banks)
  - 1,551 codes have both an SSQ and an XWB.
- **Community offset database** — `judgement_offsets.csv` in the maintainer's
  `ddr-world-universal-modpack` project (not in this repository; the
  calibration run takes its path as an argument). Consumed at runtime by that
  project's Per-Song Judgement Offsets mod
  (`src/mods/per_song_judgement_offsets/` there), generated by its
  `scripts/gen_judgement_offsets_csv.py` from a community sync list. Per the
  maintainer, the community list itself was produced by an automated tool
  ("FinalOffset" or similar), not measured by hand, and has been validated in
  play by the community.

## Semantics of the CSV

- Schema `code,p1_offset,p2_offset`; `code` is the musicdb basename, the same
  string as the SSQ/XWB basename and this tool's song code.
- Values are integer milliseconds, clamped to ±100; blank means unset.
- The value is the **compensating JUDGEMENT OFFSET**, the negation of the
  community list's recorded sync error (per the generator script's
  docstring).
- In DDR World, JUDGEMENT OFFSET (`ddr::player::Option+0x24`,
  `timing_music`) is "positive = judged later" (that project's
  `docs/per_song_judgement_offsets.md`).

**Consequence for this tool — corrected by the prototype.** The first
reading of the above was "`c > 0` means the music lands late, so `m ≈ T + c`".
The full-corpus prototype run shows the opposite unambiguously: robust
std. dev. of `m − c` is 11.1 ms, of `m + c` 0.72 ms
(`prototype-results.md` §1). So:

- `m ≈ T − c`. A song with `c > 0` has music landing `c` ms **early**
  relative to its arrows.
- Fixing it in the chart means moving the chart `c` ms earlier (subtracting
  `c` from every `tempo_data` entry).
- The modpack's "positive = judged later" is consistent with this if it means
  the player's input is treated as later, which is the right compensation for
  early music.

**Provenance and sign, confirmed 2026-09-28** (`prototype-results.md` §9). The
community tool's raw value is `−c`: "move the chart this many ms later", the
same sign as this tool's corrections. The modpack generator negates it into
the CSV. The raw values reached the generator as integers, so the CSV carries
no sub-ms information.

**Timing model.** 723 of the 1,434 analysed stock songs are TPS 150. For
those, DDR's integer-ms anchor normalization (documented in `ssq2sm.py`)
differs from raw `v / tps` timing by up to about 0.5 ms per anchor. The
community values match raw timing slightly better. **Calibrate on the 711
TPS 1000 songs**, where the two models are identical.

## Corpus statistics (2026-09-28)

| Measure | Value |
|---------|-------|
| CSV rows | 1,461 (20 blank) |
| Rows with a value | 1,441 |
| P1 ≠ P2 | 0 (always mirrored) |
| Codes with SSQ + XWB + value | 1,440 |
| Value exactly 0 (and paired) | 107 |
| \|value\| ≤ 2 ms (and paired) | 502 |
| Mean / median | −1.15 ms / −2 ms |
| Std. deviation | 6.76 ms |
| Range | −34 … +23 ms |

Distribution of values: 3 below −30 ms, 29 in [−30, −15), 269 in [−15, −5),
551 in [−5, 0), 107 at 0, 254 in (0, 5], 215 in [6, 15], 13 in [16, 30].

Konami's stock sync is therefore *not* uniform: about a fifth of the catalogue
is 10 ms or more off, but almost nothing exceeds ±35 ms.

## How the corpus is used

1. **Target `T`.** `T = median(m + c)` over all songs (corrected sign),
   cross-checked against `median(m)` over the 107 songs with `c = 0`. The two
   should agree; they do, to within 0.2 ms.
2. **Accuracy.** The spread of the residual `m + c − T` across the corpus
   measures estimator error (plus the community list's own error). This is
   the headline accuracy number for the design.
3. **Sign check.** Settled empirically: `m` correlates negatively with `c`
   (see above).
4. **Confidence thresholds (D8).** Songs with large residuals show which
   confidence signals (peak sharpness, competing peaks, split-half
   disagreement) predict a wrong answer, so thresholds come from data rather
   than guesses.

## Limits

- Stock errors are small (±35 ms), so the corpus does not exercise
  corrections near ±200 ms. Those are covered by re-scoring stock charts with
  known synthetic shifts and checking the estimator still recovers the
  community truth.
- The community values are integers produced by another automated tool, so
  residuals cannot resolve accuracy much below about ±1 ms, and agreement
  measures consistency with that play-validated tool rather than direct
  perception.
